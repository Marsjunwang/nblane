# Project Board 使用说明

Project Board 是内部项目案例页，用来把目标、任务、证据、研究资料、里程碑和输出串起来。

## 什么时候使用

- 一个工作已经超过单张 Kanban 卡，需要长期追踪。
- 需要知道哪些任务、证据或输出属于同一个项目。
- 需要把项目拆成里程碑。
- 需要复盘一个阶段内项目推进、任务完成和证据沉淀之间的关系。

## 首屏怎么看

时间轴就是整个页面。顶部工具栏放着「新建项目」「评审模式」和起止日期筛选；下面的图例那一行把概览数字折叠到右侧，让你一屏看到尽量多的项目内容：

- 进行中 / 暂停 / 已完成 / 已归档：来自 `project-board.yaml` 的项目数量。
- 未归属任务：Kanban 里还没有项目归属的任务。
- 未归属证据：已审阅但还没有项目归属的证据。
- 当前目标项目：关联到当前目标的项目数量。

如果未归属任务或证据不为 0，优先处理这些缺口。这样 Dashboard、Evidence Review 和项目复盘才能准确显示归属关系。证据本身在专门的「证据审阅」页审阅，项目看板只做关联。

## 推荐流程

1. 在工具栏点击「新建项目」，填写标题、状态、类型、可见性和摘要。表单会在时间轴上方就地展开；空看板时这就是第一步。
2. 在项目信息面板里关联当前目标、看板任务、证据、研究资料和输出。
3. 有阶段节点时添加里程碑，并把相关任务挂到里程碑下。
4. 在项目行尾用「+任务」把项目行动落到执行面，可顺带添加几个子任务。
5. 在时间轴上查看项目、任务和里程碑是否处在合理窗口。
6. 回到 Dashboard 或 Evidence Review 检查是否还有未归属项。

## 时间轴

时间轴是 Project Board 的主视图。每一行代表一个项目，左侧是项目标题、状态和摘要，右侧是任务与里程碑。

- 滚轮缩放时间范围。
- 双击重置缩放。
- 右键可以删除支持删除的项目元素。
- 进行中任务、已完成任务、已归档任务、里程碑和今天线会用不同图例显示。
- 无日期任务不会显示在时间轴上，页面会提示数量。

评审模式用于从一段时间窗口里浏览项目进展。选择起止日期后，时间轴只聚焦该窗口，适合周复盘、月复盘或阶段验收。

## 项目信息

点击项目行可以查看或编辑项目详情。常用字段包括：

- 状态：`active`、`paused`、`completed`、`archived`。
- 类型：内部、研究、工作、副业或学习。
- 可见性：内部私有或公开候选。
- 时间范围：项目开始和结束窗口。
- 摘要与备注：项目为什么存在、当前判断和后续注意事项。

Project Board 是内部工作流。即使项目可见性设为公开，也不会自动生成公开项目页；公开输出仍由 Output Studio / Public Build 负责。

## 关联引用

关联引用表示“这个项目拥有或产出了什么”，不会复制原文内容。

- 目标：说明项目服务于哪个阶段目标。
- 看板任务：说明执行工作归属。
- 证据：说明项目产出的已审阅事实。
- 研究资料：论文、URL、导入资料或来源 inbox 项。
- 经历案例：支持项目叙事的经历。
- 输出：文章、公开草稿或其他交付物。

AI 建议关联只会预填表单，不会直接写入。保存前需要人工确认。

## 里程碑与任务

里程碑适合表达项目中的可见检查点，例如“资料整理完成”“首版 demo 可用”“复盘完成”。

- 里程碑可以拥有任务、证据、研究资料和输出。
- 看板任务可以归属于项目，也可以进一步归属于某个里程碑。
- 新建任务会写入 `kanban.md`，并同步回 Project Board 的项目归属。
- 任务可以带子任务：在新建或编辑任务的表单里添加、勾选；在任务详情里以清单形式呈现。
- 任务移动到进行中时会记录开始日期；移动到已完成时会记录完成日期。

## 写入边界

本页主要写入 `project-board.yaml`。创建、移动或关联任务时，可能同步更新 `kanban.md`。关联证据或研究资料时，会保持引用关系一致，但不会改写证据正文或资料正文。

## 注意事项

- 不要把单次行动都建成项目；单张 Kanban 卡能承载的工作继续留在 Kanban。
- 如果一个项目长期没有任务、证据或输出，考虑暂停、归档或拆小。
- 未归属证据和未归属任务越少，Dashboard 和复盘页越能反映真实工作结构。
