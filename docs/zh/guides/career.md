# 求职工作台使用说明

求职工作台维护一份结构化主简历，并为每个目标岗位做 JD 匹配和定制简历。AI 只读主简历、JD、你的补充说明，
以及（可选）证据库里的事实，不读断言、技能树或看板。

## 入口

| 页面 | 路由 | 能做什么 |
| --- | --- | --- |
| 首页 | `/p/<name>/career` | 主简历卡片（照片、完成度、导出）和目标岗位列表。 |
| 主简历 | `/p/<name>/career/resume` | 按段落填写，右侧实时 A4 预览。 |
| 目标岗位 | `/p/<name>/career/jobs/<id>` | 粘贴 JD、匹配分析、生成并编辑定制简历。 |

## 主简历

主简历存在 `profiles/<name>/resume-source.yaml`，也是[公开站点](public-site.md)首页姓名、头衔、简介和照片的来源。

- **段落**：基本信息（姓名、求职头衔、电话、邮箱、所在地、网站 / GitHub、抬头补充）、个人概要、专业技能
  （可分类）、工作经历 / 项目经历 / 成果 / 教育经历（条目可分组，支持 `**加粗**`）、荣誉与其他，
  以及任意自定义段落。段落标题可以改。
- **排序**：工作经历和项目经历在简历里按时间排列，在职（结束时间留空或写「至今」）的在最前，其余按开始时间从新到旧。
  表单里的上移 / 下移只影响编辑顺序。教育经历和成果按表单顺序。
- **隐藏**：每条经历右上角的眼睛按钮可以隐藏这一条。内容留在 `resume-source.yaml`（`hidden: true`），
  预览、PDF、公开站和定制草稿里都不出现，再点一次恢复。需要压到一页时用它代替删除。
- **照片**：JPG / PNG / WebP，不超过 5 MB，存在 `media/resume/`。
- **自动保存**：编辑后自动保存，带 ETag。别处改过时暂停保存并提示刷新。
- **预览**：右侧预览与导出的 HTML / PDF 用同一套渲染。

### 导入简历

点「导入简历」，上传文件（Markdown / HTML / PDF / DOCX / TXT，不超过 10 MB）或粘贴文本。
系统先按 Markdown 或 HTML 结构识别；识别不出结构时，可以点「AI 识别字段」让 AI 按字段整理，
只搬运原文，不改写。确认后写入，替换主简历内容，照片和公开设置保留。之前的版本可以在 Git 备份里找回。

## 目标岗位

1. 首页「新建目标岗位」，填岗位标识（用作文件名，如 `智元-VLA算法`）。
2. 在「JD 与匹配」粘贴完整 JD，可选填补充说明（简历和证据里没写但真实存在的经历，或希望突出 / 回避的方向），
   可选勾选「参考证据库」。
3. 点「匹配分析」：得到总分和逐条 JD 要求的判定（符合 / 部分 / 缺失），每条附依据，并列出建议加强、
   可以弱化和真实缺口。引用不存在的证据 id 会被丢弃。
4. 点「AI 生成定制版」：候选在对比视图里打开，尚未写入。核对每条事实后「接受」，替换这份定制稿；主简历不变。
5. 在「定制简历」里继续手动编辑 Markdown，或对比主简历。

定制稿和 JD、补充说明、分析结果存在 `profiles/<name>/resumes/generated/` 下（Markdown + 同名 `.meta.yaml`）。

需要配置 LLM（`LLM_API_KEY`），没配置时 AI 识别、匹配和定制不可用，其他功能照常。

「设置 → 工作流 AI」里可以给 JD 匹配、定制简历、简历识别分别指定模型（只走兼容 API，不支持 Codex），留空用 AI 连接的默认模型。每次调用记在 `ai-runs.yaml`，失败出现在首页「AI 异常」。定制简历被模型输出上限截断时不给候选，提示调高输出上限。

## 导出

主简历和每份定制稿都可以导出 Markdown、HTML 或 PDF（A4 一页纸）。导出在内存中渲染，不改写文件。
PDF 用服务器上的 headless Chromium 打印；找不到 Chromium 时 PDF 不可用，可以导出 HTML 后用浏览器打印。
